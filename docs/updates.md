# Installation and signed updates / Instalace a podepsané aktualizace

## Architecture

Only the companion applications load Sparkle 2.10.0 / WinSparkle 0.9.4.
Neither screen saver loads updater code or accesses the network. Dependencies
are fetched from upstream releases with pinned SHA-256 hashes by
`script/fetch_updaters.py`. Runtime licenses ship with the companion/installer.
The Windows C++ runtime is statically linked in MSVC builds; all other
non-updater DLL dependencies are system components of supported Windows.

First installation is a per-user macOS DMG flow or a Windows Inno Setup EXE.
The Mac app lives at `~/Applications/ARose Preview.app`, with its managed saver
at `~/Library/Screen Savers/ARose.saver`. Sparkle updates the app including the
embedded saver; on relaunch its newer bundle build is copied to the managed
location. This does not touch ScreenSaverDefaults or saved figures. Inno Setup
updates a stable per-user installation and does not overwrite ARose preferences.
Standalone `.saver.zip` and `.scr` assets have no updater dependency.

Manual checking is always available in the installed companion. Weekly checking
is explicit opt-in, default off. SMAppService (macOS) / Task Scheduler (Windows)
invoke a short-lived helper hourly; a persisted gate permits a network attempt
only after seven days (including failed attempts). Sleeping/missed times are
best effort; checks defer during idle/locked sessions and never wake a device.
Disabling unregisters the job. Windows uninstall unregisters it too; on Mac,
disable checking before removing the app. Every installation requires user
confirmation in the updater; downloads and signature validation then proceed
automatically. No telemetry or GitHub credentials are used.

## Signing and release assets

The Ed25519 private key is in the signing Mac's login Keychain, account
`cz.coolajz.ARose`, generated by Sparkle's `generate_keys`. Only the public key
is in the sources. Securely back up this key outside Git before publication;
losing it breaks the installed clients' update trust. Do not generate a new key
on each build or export a private key into the project/CI artifacts.
The same Ed25519 signature format is used by both updater libraries.

Build the Mac with `script/build_and_run.sh --build`, then
`script/package_macos_installer.sh`. Build Windows natively with CMake and run
`script/package_windows.ps1`; the **build machine** needs Inno Setup 6.3+.
The user does not need Inno Setup, a C++ runtime installer, or WinSparkle setup.

After Developer ID/Authenticode signing and notarization where applicable,
copy the final Windows installer to the signing Mac's `dist/releases` and run:

```sh
python3 script/create_appcasts.py
```

The signing tool is kept at a stable path under `~/Library/Application Support/ARose Release Tools/2.10.0/` so its identity is not changed by rebuilding the project. Verification uses only the public key and never requests Keychain access.

This signs both final payloads from Keychain, verifies the signatures, and emits
`appcast-macos.xml` and `appcast-windows.xml`. It never publishes anything.
Upload **both feeds and both payloads on every stable release**. Feeds are
accessed through GitHub's `/releases/latest/download/…` route; their payload
URLs point to the immutable version tag. Do not rename/modify payloads after
signing. Tags use `v<major.minor.patch>`; increment the numeric bundle build
on every released update, in both platform resources/CMake. A draft, prerelease
or private repository is not a public update feed. No feed is currently live.

Expected release assets (replace 1.0.3 with the intended release version):

- `ARose-ScreenSaver-v1.0.3-macOS-universal.dmg` — initial installation
- `ARose-ScreenSaver-v1.0.3-macOS-update.zip` — Sparkle payload (companion + saver)
- `ARose-ScreenSaver-v1.0.3-macOS-standalone.saver.zip` — standalone bundle
- `ARose-ScreenSaver-v1.0.3-Windows-x64-Setup.exe` — initial/update installer
- `ARose-ScreenSaver-v1.0.3-Windows-x64.scr` — standalone saver
- `appcast-macos.xml`, `appcast-windows.xml`, SHA-256 checksums

Current local builds are ad-hoc/unsigned candidates. An Apple Development
certificate is **not** a Developer ID distribution certificate. Ed25519 update
signatures do not replace Gatekeeper notarization or Authenticode.

## Acceptance before publishing

- Native Windows build + installer compile, install/uninstall under a standard
  account, Czech/English UI, static CRT imports, preview/settings shortcuts.
- Opt-in/off registration, restart, sleep, locked/idle desktop deferral, no
  resident helper when no update exists, no duplicate helper/UI instances.
- Private test feed: upgrade build N to N+1 on both platforms, cancel, offline,
  no update, invalid/tampered signature rejection, preserved settings/bookmarks.
- On Mac, verify both the updated app and the saver after Sparkle relaunch;
  close/reopen System Settings if it retains the old saver bundle in its host.
- Test downloaded signed/notarized artifacts on a clean machine. Successful
  local compilation or signature tests do not establish this runtime acceptance.

## Česky

Aktualizační knihovny obsahují pouze doprovodné aplikace. Spořič nevykonává
síťové kontroly ani aktualizační práci. Ruční kontrola je dostupná tlačítkem;
týdenní se zapíná výslovně a lze ji vypnout. Po potvrzení se nová verze stáhne,
ověří podpis a nainstaluje. Nastavení a uložené obrazce se zachovají.
Samostatné `.scr` a `.saver` lze používat bez doprovodné aplikace a aktualizovat
ručně. Na Windows není nutné doinstalovávat .NET ani Visual C++ Redistributable.

Před veřejným vydáním je nutné bezpečně zálohovat podpisový klíč z Klíčenky,
dokončit distribuční podpisy a ověřit skutečný upgrade na obou systémech.
Každé stabilní vydání musí obsahovat oba aktualizační XML soubory i oba jimi
podepsané balíčky. Obsah po podpisu neupravujte. Skripty nic nezveřejňují.
